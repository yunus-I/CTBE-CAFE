Meal Management System Database Schema

Database Schema Explanation

📚 STUDENT Table

Stores information about all students in the system.

  • id: Unique identifier (UUID) - Primary Key
  • name: Student's full name
  • department: Department the student belongs to
  • year: Academic year (1, 2, 3, 4, etc.)
  • mealCardNumber: Unique meal card number
  • aauId: Unique AAU ID number
  • photoUrl: Optional link to student photo
  • createdAt: Record creation timestamp
  • updatedAt: Last update timestamp

🍽️ MEAL_RECORD Table

Records each meal consumed by a student, with a unique constraint preventing duplicate meal records for the same student on the same date for the same meal type.

  • id: Unique identifier (UUID) - Primary Key
  • studentId: References the Student table - Foreign Key
  • mealType: Type of meal (BREAKFAST, LUNCH, DINNER)
  • recordDate: Date the meal was recorded
  • createdAt: When the record was created

🔗 Relationship

One Student → Many Meal Records (One-to-Many)

Each student can have multiple meal records, but each meal record belongs to exactly one student.

📝 Key Concepts

  • PK = Primary Key (unique identifier for each row)
  • FK = Foreign Key (links to another table)
  • UK = Unique constraint (value must be unique)
  • Unique Constraint on (studentId, mealType, recordDate) = A student cannot record the same meal type twice on the same date
